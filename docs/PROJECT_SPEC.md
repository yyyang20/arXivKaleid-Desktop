# arXivKaleid Desktop 当前业务规范

本文档是当前有效的唯一核心筛选规范，只描述 Desktop 现行行为。GUI、候选快照和时间显示见 [Desktop 规范](desktop/DESKTOP_SPEC.md)，运行流程见 [运行与发布手册](OPERATIONS.md)，文件职责见 [项目结构](PROJECT_STRUCTURE.md)。旧版本行为通过 Git 和 [变更记录](CHANGELOG.md) 查询。

## 项目目标

项目从 arXiv 公开元数据中筛选与以下研究主线直接相关的论文：

- 黑洞或致密天体在强引力环境下的阴影、光子环、强引力图像、偏振图像、EVPA、Stokes 图及 EHT 尺度成像。
- 首次构造、推导或数值获得的黑洞、致密天体或可作为成像背景的严格新时空解。

系统只判断研究相关性和阅读优先级，不验证论文结论、创新性、公式正确性、代码可复现性或观测可信度。

## 候选收集与时间

Desktop 从点击时的 UTC 日期向前寻找最近非空候选日期，按完整 arXiv ID 和版本批内去重，冻结排序后最多 100 篇候选，不查询跨运行历史完成状态。分类、日期窗口、分页、单次请求和快照失效规则见 [候选抓取](desktop/DESKTOP_SPEC.md#候选抓取)；候选日期及抓取完成时间的显示见 [统计与内存快照](desktop/DESKTOP_SPEC.md#统计与内存快照)。

## Round 1

Round 1 使用同批候选的标题、摘要、分类和 `round1_v20` 内置研究边界：

- 最多输出 10 篇，可以不足或为 0。
- 模型数组顺序就是原始推荐顺序；程序只对限额内有效子集连续生成最终 Rank。
- 每项必须包含候选索引、四类内容标签和 1 至 300 字的具体中文理由；摘要证据为可选字段。
- 只有 `成像`、`新解`、`成像｜新解`可以有效入围；`其他`逐篇排除。
- 单篇身份、重复、标签或理由错误只排除该篇；无效可选证据只丢弃证据并计数。
- 限额外输出忽略，限额内排除后不得从外部候选补位，不得按标签、分数或其他语义自动重排。

## PDF 与全文门控

Round 1 有效入围后逐篇处理精确版本 PDF：

- 核验 arXiv 身份、版本、PDF 签名、SHA-256 和实际物理页数。
- 已确认撤稿且无法取得精确版本 PDF、下载失败、身份不符、页数无法确认或全文提取失败时，只排除该篇，不补位。
- 实际页数不超过 60 页时提取带页码的完整全文，供 Round 2 使用。
- 超过 60 页时标记为长篇，不进入 Round 2，也不由其他候选补位。
- 单篇请求 Token 超限时排除该篇；全部排除时跳过 Round 2 模型并生成 0 篇日报。
- PDF 只保存在本地运行目录，不进入 Git、主 SQLite 或发行包。逐页全文保存在当前 `work/round2_inputs.sqlite` 工作库中，不进入日志或发行包。

## Round 2

Round 2 必须同时阅读门控后的全部合格全文：

- 最多输出 5 篇，可以不足或为 0。
- 每项只包含精确 arXiv 身份、全文内容标签和 1 至 300 字的具体中文理由。
- 第二轮标签以全文为准，可以覆盖 Round 1 标签。
- 只有前三类核心标签可以形成最终推荐；`其他`、身份错误、重复、非法标签或空理由逐篇排除。
- 模型数组顺序保持不变，程序不按标签或分数重排，也不补位。
- 推荐级别由程序按最终有效名次确定：第 1 篇 `deep_read`，第 2 至 4 篇 `skim_read`，第 5 篇 `backup`。

## 内容标签

当前两轮统一使用四类标签：

| 标签 | 定义 |
|---|---|
| `成像` | 实际生成、分析或观测目标强引力图像，但没有新时空解 |
| `新解` | 首次给出可核实、可作为成像背景的新时空解，但没有实际成像 |
| `成像｜新解` | 同时严格满足成像和新解 |
| `其他` | 不满足核心定义，包括仅相关方法、吸积或辐射模型、测地线、偏折、QNM、稳定性、内部物态或一般修正引力 |

当前筛选和日报不使用旧理由码、A–E 层级或入选性质。

## 模型传输与调用

- 两轮均使用思考模式和本地严格 JSON 校验；`reasoning_content` 永远不能作为正式答案。
- Round 1 使用 Chat Completions，正式答案必须是完整 JSON 对象或占据全部内容的单一 JSON 代码块。Round 2 使用 Responses API，提供唯一命名函数但不发送强制 `tool_choice`；程序只解析唯一且名称匹配的 `function_call.arguments`，不读取消息文本或推理内容，也不启用 beta strict。损坏 JSON、缺失或多个函数调用、函数名及任务或版本身份错误均失败。
- GUI Key 在内存中显式注入两轮客户端；不读取传统 Secret 文件，不执行付费 self check。
- 不保存或打印模型原始响应、完整 prompt、全文、请求头或 Secret。
- 每个逻辑模型调用最多发送一次 HTTP 请求；超时、API、空内容、JSON 或业务校验失败后保存安全审计、usage 和费用并停止，不自动重试。`empty_content` 是模型/API 失败，不是零推荐的正常结果。
- 缓存身份绑定完整请求、候选顺序、模型、Prompt 版本、`profile_v2` 兼容身份和选择策略；损坏或不兼容缓存必须拒绝。

## Desktop 日报

`desktop/report.py` 从当前 run 的 SQLite 装载事实，使用 `rebuild_daily_report.py` 的数据读取辅助函数和 `generate_round2_report.py` 的 Round 2 推荐区块生成 GUI Markdown：

- 显示候选日期、两轮输入和结果数量、实际模型、Token 与费用，再显示 Round 2 最终推荐和 Round 1 入围详情。
- 无候选、Round 1 零入选、Round 2 零入选以及无合格全文而跳过 Round 2 都是正常零结果；不虚构未执行的模型调用。
- 标签、Rank、PDF 页数、门控状态、usage 和费用来自当前工作库，不显示分数、置信度、入选性质、证据或单篇 Token 估算。
- Round 2 展示完整公开摘要和可见推荐级别；Round 1 不重复全部摘要。
- 仅打开正常的 HTTPS arXiv 摘要和 PDF 链接，本地 PDF 以相对路径信息显示。
- 日报只在 GUI 显示，不写根 `reports/`，没有编辑、导出或历史管理功能。

数据层负责身份、计数和数据库事实，展示层只负责 Markdown 排版。具体渲染和展示失败处理见 [Desktop 日报](desktop/DESKTOP_SPEC.md#desktop-日报)。

## SQLite 工作数据

主工作库 `work/arxiv_kaleid.sqlite` 保存当前分析的论文元数据、运行、两轮结果、审计、缓存、完成状态、PDF 状态、模型调用、usage、费用和阶段耗时；主库 schema 为 v1，未知版本拒绝使用。独立全文库 `work/round2_inputs.sqlite` 保存物理页数、逐页全文和输入门控决定。

这些工作库只服务当前 attempt，不是跨运行历史数据库。固定工作库重置、sidecar、文件锁及 PDF 保留方式见 [一次性两轮分析](desktop/DESKTOP_SPEC.md#一次性两轮分析)。SQLite、PDF、报告、日志和缓存不得提交 Git。

## Token 与费用

- Round 1 和 Round 2 请求各自执行保守 Token 预检；输入上限、输出上限、上下文安全余量、价格快照和费用公式以当前配置为准。
- 费用预检始终使用峰值费率，实际调用按每个 HTTP 请求前的北京时间价格档位固化。
- 单批费用上限为 ¥3.00，配置可收紧；下一轮预检累计本批已发生费用，usage 或费用无法确认时停止后续调用。
- 费用按调用时快照保存，不按未来价格重算。
- 任意模型调用都必须获得用户当次授权，且不得自动重跑。

## 失败边界

逐篇排除：单篇身份、重复、非法标签、空理由、无效可选证据、撤稿、PDF 下载、页数、全文提取或单篇 Token 问题。PDF/全文阶段以实际影响范围为准：异常位于已建立的单篇边界、共享组件和 SQLite 完整且单篇失败成功持久化时，即使异常类型此前未枚举，也保持单篇失败。

整批停止：顶层 JSON 或关键数组错误、任务或版本身份错误、模型/API 错误、数据库损坏、共享依赖或组件初始化、runtime 共享存储、资源身份、费用、整批 Token 或候选集合错误。无法证明异常只影响单篇时失败关闭。“无成功 PDF”或“无合格全文”只有在全部原因均为已确认单篇排除或正常门控，且共享完整性检查通过时才是正常结果。

任何失败都不得用 Round 1 冒充 Round 2，不得生成虚假成功状态，不得自动补位、重排或重跑。当前 Desktop 不自动重试候选请求或模型调用；重新分析必须重新获取候选。

## 验收标准

- 只分析当前冻结快照，最多 100 篇，不查询跨运行历史候选。
- Round 1 有效结果为 0 至 10 篇，Round 2 为 0 至 5 篇。
- PDF、全文、页数、身份、标签、Rank、时间、usage 和费用均可追溯。
- 单篇错误与系统错误按规定分流，零推荐是有效结果。
- GUI 日报、当前工作库计数与实际调用事实一致。
- Secret、模型原始响应、完整 prompt、全文和本地敏感路径不进入日志或发行包。
- 完整离线测试和必要静态检查通过。
