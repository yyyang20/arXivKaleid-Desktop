# arXivKaleid Desktop 当前业务规范

本文档是当前有效的唯一核心筛选规范，只描述 Desktop 现行行为。GUI、候选快照和时间显示见 [Desktop 规范](desktop/DESKTOP_SPEC.md)，运行流程见 [运行与发布手册](OPERATIONS.md)，文件职责见 [项目结构](PROJECT_STRUCTURE.md)。旧版本行为通过 Git 和 [变更记录](CHANGELOG.md) 查询。

## 项目目标

项目按用户分别编写的两轮完整研究 Prompt 筛选 arXiv 论文。研究方向、筛选标准、排除条件、评价方式、严格程度和排序要求全部由用户定义；分析引擎没有内置领域筛选规则。

模型生成内容不保证论文结论、公式、创新性、复现性或观测可信度。程序只校验自动化所需的身份、结构、顺序和资源安全边界。

## 完整研究 Prompt

用户编辑完整研究提示词，不再补充固定研究协议。默认的主要贡献判断、明确程度、阅读价值、查准率优先和宁缺毋滥只是可修改建议；没有固定标签、领域理由或阅读级别。两轮默认正文包含相应公式与文本格式提醒，可编辑、删除、保存及恢复，技术层不隐藏添加研究提醒。边界核对见 [Prompt 层次核对](desktop/PROMPT_SPLIT.md)。提示词不作为代码或模板执行，不能突破技术协议及安全门禁。

每轮保存一份当前运行根 `config/roundN_research_prompt.json`，格式 `research_prompt_v1`，`research_prompt` 为字符串或 null；缺失/null 表示内置默认。两轮独立，重启恢复；不读取或迁移 alpha10 覆盖记录。文本统一 LF，拒绝空白、NUL、无效 Unicode 和超过 10,000 字符。原子替换成功才更新生效状态；损坏/未知格式保留文件并阻止分析，确认恢复本轮默认后才替换。

告知和必要检查通过后、消费候选快照前读取两轮保存值并冻结进 attempt；未保存草稿和运行中的后续文件变更不进入本批请求。实际文字进入完整请求哈希、Round 2 缓存身份及 Token/上下文/累计费用预检；日志和数据库审计不保存原始 Prompt 正文。模型仍可能违反自然语言要求，技术安全边界由本地结果校验执行。

## 候选收集与时间

Desktop 只查询用户所选北京时间自然日：论文首次提交时间 `published` 换算成北京时间后落在该日，且执行抓取时已经能从 API 查询到。此定义不是 arXiv 公告批次日；同日不同抓取时刻可以得到不同数量，查不到统一作为无候选，不自动回退。三个固定分类完整分页后，按完整 arXiv ID 和版本批内去重，冻结排序后的全部候选，不查询跨运行历史完成状态。分类、日期窗口、分页、单次请求和快照失效规则见 [候选抓取](desktop/DESKTOP_SPEC.md#候选抓取)；日期及完成时间显示见 [统计与内存快照](desktop/DESKTOP_SPEC.md#统计与内存快照)。

## Round 1

Round 1 使用同批候选的标题、摘要、必要身份、`round1_v22` 技术协议和当次冻结的第一轮完整研究 Prompt；作者与分类仅保存在本地供展示：

- 最多输出 10 篇，可以不足或为 0。
- 全部去重候选进入同一次请求，没有论文篇数上限；安全预检超限时停止，不截断、抽样、拆批或提高限额。
- 模型数组顺序就是原始推荐顺序；程序只对限额内有效子集连续生成最终 Rank。
- 每项仅必填 `candidate_index`，可选 `evaluation` 为自由文本；语言、标签、评分、理由及阅读建议不设研究约束，也不截断到 300 字。
- 缺省或空评价仍可入围；评价类型、NUL 或 Unicode 结构错误仅丢弃可选评价并计数，不排除合法论文身份。
- 单篇身份或重复错误只排除该篇。额外字段忽略并记录数量，不参与筛选。
- 限额外输出忽略，限额内排除后不得从外部候选补位，不得按标签、分数或其他语义自动重排。

## PDF 与全文门控

Round 1 有效入围后逐篇处理精确版本 PDF：

- 核验 arXiv 身份、版本、PDF 签名、SHA-256 和实际物理页数。
- 已确认撤稿且无法取得精确版本 PDF、下载失败、身份不符、页数无法确认或全文提取失败时，只排除该篇，不补位。
- 实际页数不超过 60 页时提取带页码的完整全文，供 Round 2 使用。
- 超过 60 页时标记为长篇，不进入 Round 2，也不由其他候选补位。
- 保留原整批请求 Token 超限处理：优先排除单篇载荷最大者，并列按 arXiv ID 和版本固定顺序，不参考第一轮研究排名；每次重新序列化估算。全部排除时跳过 Round 2 模型并生成 0 篇日报。
- PDF 只保存在本地运行目录，不进入 Git、主 SQLite 或发行包。逐页全文保存在当前 `work/round2_inputs.sqlite` 工作库中，不进入日志或发行包。

## Round 2

Round 2 输入为门控后论文的标题、摘要、必要身份及逐页提取全文，按 `(arxiv_id, version)` 升序排列。不得输入第一轮评价、标签、理由、评分、证据或排名，也不以第一轮推荐顺序排列；本轮完整 Prompt 独立决定研究判断：

- 最多输出 5 篇，可以不足或为 0。
- 每项仅必填精确 `arxiv_id`、`version`，可选 `evaluation` 自由文本；评价规则与第一轮相同。
- 身份错误或重复逐篇排除，没有领域标签门禁或强制理由。
- 模型数组顺序保持不变，程序不按标签或分数重排，也不补位。
- 程序不生成固定阅读级别；用户需要的评价或阅读建议可由模型写入自由评价。

## 最小技术协议

保留两轮原有顶层任务、版本和策略身份回显、有序结果数组、候选成员校验及 10/5 数量上限。技术协议和命名函数 schema 不包含研究标签枚举或评价标准。可选自由评价不参与程序筛选、重排或 PDF/Token 裁决。

## 模型传输与调用

- 两轮均使用思考模式和本地严格 JSON 校验；`reasoning_content` 永远不能作为正式答案。
- Round 1 使用 Chat Completions，正式答案必须是完整 JSON 对象或占据全部内容的单一 JSON 代码块。Round 2 使用 Responses API，提供唯一命名函数但不发送强制 `tool_choice`；程序只解析唯一且名称匹配的 `function_call.arguments`，不读取消息文本或推理内容，也不启用 beta strict。损坏 JSON、缺失或多个函数调用、函数名及任务或版本身份错误均失败。
- GUI Key 在内存中显式注入两轮客户端；不读取传统 Secret 文件，不执行付费 self check。
- 不保存或打印模型原始响应、完整 prompt、全文、请求头或 Secret。
- 每个逻辑模型调用最多发送一次 HTTP 请求；超时、API、空内容、JSON 或业务校验失败后保存安全审计、usage 和费用并停止，不自动重试。`empty_content` 是模型/API 失败，不是零推荐的正常结果。
- 缓存身份绑定完整请求、候选顺序、模型、Prompt 版本、`profile_v2` 兼容身份和选择策略；损坏或不兼容缓存必须拒绝。

## Desktop 日报

`desktop/report.py` 从当前 run 的 SQLite 装载事实，使用 `rebuild_daily_report.py` 的数据读取辅助函数和 `generate_round2_report.py` 的 Round 2 推荐区块生成 GUI Markdown：

- 显示候选日期、两轮输入和结果数量、实际模型、Token 与费用，再显示 Round 2 最终推荐和 Round 1 入围详情。
- 无候选、Round 1 零入选、Round 2 零入选以及无合格全文而跳过 Round 2 都是正常零结果；不虚构未执行的模型调用。
- 两轮顺序、可选评价、PDF 页数、门控状态、usage 和费用来自当前工作库；没有强制标签、分数或阅读级别。自由评价按安全文本展示，不作为 HTML 或可执行链接解释。
- Round 2 展示完整公开摘要；Round 1 不重复全部摘要，不把第一轮评价继承为第二轮评价。
- 仅打开正常的 HTTPS arXiv 摘要和 PDF 链接，本地 PDF 以相对路径信息显示。
- 日报在 GUI 显示，不写根 `reports/`，没有编辑或导出功能。完整分析成功后将当次原始 Markdown 与计数保存到独立历史库，不重新生成历史日报。

数据层负责身份、计数和数据库事实，展示层只负责 Markdown 排版。具体渲染和展示失败处理见 [Desktop 日报](desktop/DESKTOP_SPEC.md#desktop-日报)。

## SQLite 工作数据

主工作库 `work/arxiv_kaleid.sqlite` 保存当前分析的论文元数据、运行、两轮结果、审计、缓存、完成状态、PDF 状态、模型调用、usage、费用和阶段耗时；主库 schema 为 v1，未知版本拒绝使用。独立全文库 `work/round2_inputs.sqlite` 保存物理页数、逐页全文和输入门控决定。

这些工作库只服务当前 attempt，不是跨运行历史数据库。自由评价保存在现有 `reason` 列，`details_json` 仅保存模型位置，兼容列 `recommendation_level`、`score`、`confidence` 置空；不改变表结构或迁移旧工作数据。固定工作库重置、sidecar、文件锁及 PDF 保留方式见 [一次性两轮分析](desktop/DESKTOP_SPEC.md#一次性两轮分析)。SQLite、PDF、报告、日志和缓存不得提交 Git。

独立历史库 `history/history.sqlite` 使用 schema v2，保存 operation ID、UTC 微秒日报完成时间及抓取完成时间、ISO 论文日期、候选数、最终推荐数和原始 Markdown；同日多次成功分别保存，按日报完成时间及入库序号倒序。抓取完成时间与论文日期直接来自本次冻结快照 `completed_at`、`candidate_date`；候选数取快照 `round1_count`，最终推荐数取已校验的分析结果，不解析 Markdown 推算日期或计数。正常零推荐保存，抓取、分析或日报生成失败不保存。历史写入在最终分析成功后独立尝试一次，失败不改写工作库成功、不触发重新分析；读取、删除及未知 schema 错误也不重建或清空历史。页面、保留与删除规则见 [日报历史](desktop/DESKTOP_SPEC.md#日报历史)。

## Token 与费用

- Round 1 和 Round 2 请求各自执行保守 Token 预检；输入上限、输出上限、上下文安全余量、价格快照和费用公式以当前配置为准。
- 费用预检始终使用峰值费率，实际调用按每个 HTTP 请求前的北京时间价格档位固化。
- 单批费用上限为 ¥3.00，配置可收紧；下一轮预检累计本批已发生费用，usage 或费用无法确认时停止后续调用。
- 两轮请求输入上限均为 800,000 Token，模型上下文为 1,000,000，安全余量为 72,000；每轮实际最大输出为 128,000，配置输出硬上限为 384,000，自动模型重试为 0。
- 预检停止使用分轮稳定错误码，说明本轮未调用；Round 2 停止不抹去 Round 1 已发生的结果、调用与费用。
- 费用按调用时快照保存，不按未来价格重算。
- 任意模型调用都必须获得用户当次授权，且不得自动重跑。

## 失败边界

逐篇排除：单篇身份、重复、撤稿、PDF 下载、页数、全文提取或 Token 门控问题；无效可选评价仅丢弃该字段。PDF/全文阶段以实际影响范围为准：异常位于已建立的单篇边界、共享组件和 SQLite 完整且单篇失败成功持久化时，即使异常类型此前未枚举，也保持单篇失败。

整批停止：顶层 JSON 或关键数组错误、任务或版本身份错误、模型/API 错误、数据库损坏、共享依赖或组件初始化、runtime 共享存储、资源身份、费用、整批 Token 或候选集合错误。无法证明异常只影响单篇时失败关闭。“无成功 PDF”或“无合格全文”只有在全部原因均为已确认单篇排除或正常门控，且共享完整性检查通过时才是正常结果。

任何失败都不得用 Round 1 冒充 Round 2，不得生成虚假成功状态，不得自动补位、重排或重跑。当前 Desktop 不自动重试候选请求或模型调用；重新分析必须重新获取候选。

## 验收标准

- 只分析当前冻结快照的全部去重候选，不查询跨运行历史候选。
- Round 1 有效结果为 0 至 10 篇，Round 2 为 0 至 5 篇。
- PDF、全文、页数、身份、两轮顺序与评价、时间、usage 和费用均可追溯；无隐藏研究筛选或第一轮排名泄漏。
- 单篇错误与系统错误按规定分流，零推荐是有效结果。
- GUI 日报、当前工作库计数与实际调用事实一致。
- Secret、模型原始响应、完整 prompt、全文和本地敏感路径不进入日志或发行包。
- 完整离线测试和必要静态检查通过。
