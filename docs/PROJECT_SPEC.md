# arXivKaleid 当前业务规范

本文档是 arXivKaleid 当前有效的唯一业务规范，只描述现行行为。运行和上线流程见 [运行与发布手册](OPERATIONS.md)，文件职责见 [项目结构](PROJECT_STRUCTURE.md)。旧版本行为和具体运行记录只从 Git、PR、Issue 与 artifact 查询。

## 项目目标

项目从 arXiv 公开元数据中筛选与以下研究主线直接相关的论文：

- 黑洞或致密天体在强引力环境下的阴影、光子环、强引力图像、偏振图像、EVPA、Stokes 图及 EHT 尺度成像。
- 首次构造、推导或数值获得的黑洞、致密天体或可作为成像背景的严格新时空解。

系统只判断研究相关性和阅读优先级，不验证论文结论、创新性、公式正确性、代码可复现性或观测可信度。

## 正式候选收集

正式 `schedule`、手动 `full` 和 `manual_backfill` 共用同一候选收集器：

- 以明确的数据截止时间为上界，按当前 arXiv 版本的 `updated DESC` 从新到旧扫描。
- 同一时间按 arXiv ID、版本号升序稳定排序。
- 扫描分类为 `gr-qc`、`astro-ph.HE` 和 `astro-ph.GA`。
- 每个分类每页最多 1000 条，最多 20 页；跨分类按 arXiv ID 和版本去重。
- 同一论文的不同版本是不同候选，可以分别处理。
- 排除滚动账本中已处理的相同版本，最多将前 100 篇放入本批，其余未处理版本留在队列。
- 达到 100 篇即停止；不足 100 篇按实际数量运行；0 篇生成零费用空日报。
- 正式候选扫描不设置固定日历天数下限，只要未达到上限就继续向更早版本扫描。
- 单次 arXiv 元数据请求超时为 90 秒；只有 HTTP 429、HTTP 5xx 或超时可在等待 60 秒后重试一次。其他 HTTP、XML、排序、身份或数据结构异常立即停止；唯一一次重试仍失败时也必须在模型调用前停止。
- 扫描到页数上限仍不足 100 篇不是错误。

传统本地 `main.py` 和 `preview_arxiv_metadata.py --as-of-date` 保留按 `submittedDate` 回退的诊断兼容逻辑，不代表正式自动化候选策略，也不得用于替代滚动账本。

## Round 1

Round 1 使用同批候选的标题、摘要、分类和 `round1_v20` 内置研究边界：

- 最多输出 10 篇，可以不足或为 0。
- 模型数组顺序就是原始推荐顺序；程序只对限额内有效子集连续生成最终 Rank。
- 每项必须包含候选索引、四类内容标签和 1 至 300 字的具体中文理由；摘要证据为可选字段。
- 只有 `成像`、`新解`、`成像｜新解`可以有效入围；`其他`逐篇排除。
- 单篇身份、重复、标签或理由错误只排除该篇；无效可选证据只丢弃证据并计数。
- 限额外输出忽略，限额内排除后不得从外部候选补位，不得按标签、分数或其他语义自动重排。

## PDF 与全文门控

Round 1 有效入围后逐篇处理精确版本 PDF：

- 核验 arXiv 身份、版本、PDF 签名、SHA-256 和实际物理页数。
- 已确认撤稿且无法取得精确版本 PDF、下载失败、身份不符、页数无法确认或全文提取失败时，只排除该篇，不补位。
- 实际页数不超过 60 页时提取带页码的完整全文，供 Round 2 使用。
- 超过 60 页时标记为长篇，不进入 Round 2，也不由其他候选补位。
- 单篇请求 Token 超限时排除该篇；全部排除时跳过 Round 2 模型并生成 0 篇日报。
- PDF 文件不得进入 Git、主 SQLite、公开报告或长期 artifact。逐页全文只保存在私有短期 `round2_inputs.sqlite` 中。

## Round 2

Round 2 必须同时阅读门控后的全部合格全文：

- 最多输出 5 篇，可以不足或为 0。
- 每项只包含精确 arXiv 身份、全文内容标签和 1 至 300 字的具体中文理由。
- 第二轮标签以全文为准，可以覆盖 Round 1 标签。
- 只有前三类核心标签可以形成最终推荐；`其他`、身份错误、重复、非法标签或空理由逐篇排除。
- 模型数组顺序保持不变，程序不按标签或分数重排，也不补位。
- 推荐级别由程序按最终有效名次确定：第 1 篇 `deep_read`，第 2 至 4 篇 `skim_read`，第 5 篇 `backup`。

## 内容标签

当前两轮统一使用四类标签：

| 标签 | 定义 |
|---|---|
| `成像` | 实际生成、分析或观测目标强引力图像，但没有新时空解 |
| `新解` | 首次给出可核实、可作为成像背景的新时空解，但没有实际成像 |
| `成像｜新解` | 同时严格满足成像和新解 |
| `其他` | 不满足核心定义，包括仅相关方法、吸积或辐射模型、测地线、偏折、QNM、稳定性、内部物态或一般修正引力 |

旧理由码、A–E 层级和入选性质只用于读取历史产物，当前筛选和日报不得使用。

## 模型传输与调用

- 两轮均使用思考模式和本地严格 JSON 校验；`reasoning_content` 永远不能作为正式答案。
- Round 1 继续使用 Chat Completions，正式答案必须是完整 JSON 对象或占据全部内容的单一 JSON 代码块。Round 2 使用 Responses API，提供唯一命名函数但不发送思考模式不支持的强制 `tool_choice`；程序只解析唯一且名称匹配的 `function_call.arguments`，不读取消息文本或推理内容，也不启用 beta strict。损坏 JSON、缺失或多个函数调用、函数名及任务或版本身份错误均失败。
- 不保存或打印模型原始响应、完整 prompt、全文、请求头或 Secret。
- 每个逻辑模型调用最多发送一次 HTTP 请求；超时、API、空内容、JSON 或业务校验失败后保存安全审计、usage 和费用并停止，不自动重试。
- 缓存身份绑定完整请求、候选顺序、模型、Prompt 版本、`profile_v2` 兼容身份和选择策略；新版本不得命中旧缓存，损坏或不兼容缓存必须拒绝。

## 时间与运行模式

| 模式 | 报告日期和数据截止时间 |
|---|---|
| 自动 schedule | 实际启动前最近的北京时间 18:03 计划槽位 |
| 手动 `full` | 显式计划日期的北京时间 18:03 |
| 手动回查 | 指定日期的北京时间 23:59:59 |
| 受控重做 | 继承原批次报告日期和截止时间 |

自动模式的实际生成时间可以跨日，但标题日期保持计划槽位日期，并记录调度延迟。手动回查不显示调度延迟。`publish_recovery` 必须继承已保存的时间信息，不得重新计算。

## 正式日报

唯一正式日报重建入口为 `rebuild_daily_report.py`，正式模板由 `daily_report_template.py` 集中提供外壳：

- 报告顺序为“本次运行”、Round 2 最终推荐、Round 1 入围论文、折叠自动化审计。
- 无候选、Round 1 零入选、Round 2 零入选以及无合格全文而跳过 Round 2 都是标准日报的正常退化；四段结构不变，只替换实际计数和空结果说明。
- 模型、Token 和费用必须来自当前 run 的成功调用账本：没有调用显示“未调用”；只调用 Round 1 时不得虚构 Round 2 模型或调用。
- Round 1 和 Round 2 计数各占一行；Round 2 行通过一个 `<br>` 紧接 `成像`、`新解`、`成像｜新解`和`未推荐`数量。
- `未推荐`等于 Round 2 输入数减最终有效结果数。
- 两轮都显示合并后的 arXiv ID、当前版本提交日期、作者、分类、标签、实际 PDF 页数和理由；Round 2 另显示对应 Round 1 Rank 和首字母大写的可见推荐级别。
- Round 2 显示完整公开摘要；Round 1 不重复全部摘要。
- 不显示模型原始位置、分数、置信度、入选性质、证据、阅读范围或单篇 Token 估算。
- 云端报告只允许在线摘要页和在线 PDF 链接，不得包含用户电脑或 runner 的本地路径。
- 隐藏元数据、可见计数、实际模型调用、SQLite 标签、Round 1 Rank、全文页数、时间和报告哈希必须一致，否则禁止发布；合法的 0 至 5 篇结果不得因空列表本身被拒绝。
- 历史模板只读兼容，不得用新模板覆写旧报告。

日报数据层负责身份、计数、时间和数据库事实；展示层只负责 Markdown 排版。普通换行、标点和字段顺序修改不应改变筛选或数据库逻辑。

## SQLite 与 artifact

主 SQLite 保存论文元数据、运行、两轮结果、审计、缓存、PDF状态、模型调用、usage、费用、日报身份、错误样本和自动化账本。当前自动化 schema 为 v5。

滚动 artifact 必须使用 allowlist、manifest 和 SHA-256 校验，并按 generation 保存状态。数据库必须通过 `PRAGMA integrity_check`；来源 artifact、候选集合、父代、策略哈希或文件集合不一致时硬失败。B28 固定兼容入口仍同时锁定策略哈希、Batch、Batch 身份、generation、发布 Run、Issue 和发布状态，只允许前向接续一次；随后新账本使用当前 v22 策略。运行数据、SQLite、PDF、报告、日志和缓存不得提交 Git。

Round 2 返回空内容（`empty_content`）是模型/API失败，不是“Round 2 零入选”的正常退化。系统必须先发布失败 Issue 与 G7，并保留精确的已发布失败账本作为一次人工恢复来源。仍符合恢复规则的 v21 旧 Round 2 必须保持 `round2_v14 + profile_v2` 原请求语义：固定校验旧 Prompt、Profile JSON、候选顺序、全文、工具 schema 和原请求哈希，不迁移为 v15，不改写来源策略身份。仅在新的明确授权下，恢复才可复用原 Round 1 入围论文和合格全文，增加一次 Round 2 HTTP 请求；不得重抓、重跑 Round 1、重做 PDF 门控或自动重试。使用 v20/v15 重新筛选历史候选只能走 `controlled replay`，新缓存、调用账本和结果与原恢复链分离。恢复得到有效 JSON 后，Top 0 至 5 均可发布，但只能替换该来源绑定的失败 Issue，并写入新的正常 G7；来源、Issue、哈希、费用、恢复次数或谱系不一致即停止。

## 错误样本库

`screening_error_samples` 与历史 `feedback` 表完全分离，固定字段为：

```text
batch_id
arxiv_id
version
error_type
correct_label
reason
reviewed_by
created_at
```

- 只记录经用户或 Agent 确认的最终 Round 2 `漏选`、`误选`和`错标`，存疑论文不写入。
- 正确标签只能是四类内容标签，原因为 1 至 300 字单段具体说明，复核者只能是 `user` 或 `agent`。
- 同一 Batch、arXiv ID 和版本只能有一条；完全相同内容幂等成功，任何冲突不得覆盖。
- `漏选`要求论文未进入最终推荐且正确标签不是 `其他`；`误选`要求已推荐且正确标签为 `其他`；`错标`要求已推荐且正确非其他标签不同于已保存标签。
- 只允许写入正常发布的 generation 7 批次候选，输入整批验证、单事务提交。
- 错误样本只用于积累和人工复盘，不自动进入提示词。修改提示词必须另行授权并创建新版本。

历史 `feedback` 仅为旧数据兼容，当前筛选、日报和错误样本流程均不读取它。

## Token 与费用

- Round 1 和 Round 2 请求各自执行保守 Token 预检；输入上限、输出上限、上下文安全余量、价格快照和费用公式以配置及自动化策略为准。
- 费用预检始终使用峰值费率，实际调用按每个 HTTP 请求前的北京时间价格档位固化。
- 单批预期费用和工作流绝对上限均为 ¥3.00；受控重做还必须提供不超过该边界的显式单次上限。
- 历史费用按调用时快照保存，不按未来价格重算。
- 任意模型调用都必须获得用户当次授权，且不得自动重跑。

## 失败边界

逐篇排除：单篇身份、重复、非法标签、空理由、无效可选证据、撤稿、PDF下载、页数、全文提取或单篇 Token 问题。PDF/全文阶段以实际影响范围为准：异常位于已建立的单篇边界、共享组件和 SQLite 完整且单篇失败成功持久化时，即使异常类型此前未枚举，也保持单篇失败。

整批停止：顶层 JSON 或关键数组错误、任务或版本身份错误、模型/API错误、数据库或 artifact 损坏、共享依赖或组件初始化、runtime 共享存储、策略哈希、费用、整批 Token、候选集合、父代或发布完整性错误。无法证明异常只影响单篇时失败关闭。“无成功 PDF”或“无合格全文”只有在全部原因均为已确认单篇排除或正常门控，且共享完整性检查通过时才是正常结果。

任何失败都不得用 Round 1 冒充 Round 2，不得生成虚假成功状态，不得自动补位、重排或重跑。除上述同一元数据请求的唯一一次瞬态重试外，任何模型、PDF、发布、恢复或批次失败都不得自动重试。

## 验收标准

- 正式候选按锚点前 `updated` 顺序最多处理 100 个未处理版本。
- Round 1 有效结果为 0 至 10 篇，Round 2 为 0 至 5 篇。
- PDF、全文、页数、身份、标签、Rank、时间、usage 和费用均可追溯。
- 单篇错误与系统错误按规定分流，0 篇日报是有效结果。
- 报告、SQLite、manifest、Issue 和 generation 状态一致。
- Secret、模型原始响应、完整 prompt、全文和本地敏感路径不进入日志或公开产物。
- 完整离线测试、静态检查和获准的云端零费用验证通过。
